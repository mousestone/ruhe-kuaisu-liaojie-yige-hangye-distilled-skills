# 金字塔原理资讯提炼

## R — 原文 (Reading)

> "罗列资讯:将所有重要资讯写在便笺纸上……寻找规律:尝试提炼不同资讯的共性……提炼要点:分组后，分别为每个组提炼一个要点。归纳核心:思考每个组的要点对于问题到底意味着什么。"
>
> — 肖璟，《如何快速了解一个行业》第11章 第2节

## I — 方法论骨架 (Interpretation)

把一堆杂乱资讯变成"有深度的核心观点",走四步,像搭金字塔:

1. **罗列资讯**——把所有重要信息写成完整语句(不是关键词),摊开在面前。
2. **寻找规律**——找出它们的共性,分组成几条(分组要符合 MECE:不重不漏)。
3. **提炼要点**——每组用一句话提炼出关键论述。
4. **归纳核心**——追问"这些要点对问题到底意味着什么",把顶层的核心观点推出来。

**最关键的纪律:区分"总结"和"提炼"。** 总结是把原文缩句,零信息增量,小学生都会;提炼要产生新认知、有深度。区分的方法就是反复问 **"So what?(那又怎样?)**"——从 Know-what(是什么)推到 Know-how(怎么办)再推到 Know-why(为什么),直到得出可操作的结论。看到一个结论就问:它改变什么?下一步该做什么?若答不上来,说明还在总结层。

**推理补足**:分组和上推时用归纳推理(从事实找共性提炼规律)或演绎推理(从前提到结论推演)。

## A1 — 书中的应用 (Past Application)

### 案例 1:ABC 房企邮件——金字塔原理重构资讯
- **问题**: 前同事 H 买了某房企的票据,要写邮件提醒他催款。
- **方法论的使用**: 第一版"想到哪儿写到哪儿",信息密集但记不住;第二版用金字塔原理:核心结论先行("你需要及时向 ABC 房企催款"),依据按"融资现金流-投资现金流-营运现金流"MECE 分类(融资不好融/资产不够卖/房子不好卖)。
- **结论**: 结论→三组依据,逻辑清晰、资讯高效传达。
- **结果**: 第二版邮件明显优于第一版,体现金字塔的应用价值。

### 案例 2:"找不到钥匙"——总结 vs 提炼
- **问题**: 一个"我找不到钥匙和身份证、延误了报税"的叙事,什么才是提炼?
- **方法论的使用**: 复述"我丢了钥匙所以延误报税"只是总结(缩句);追问 So what——这反映的是"关键时刻习惯性不检查随身物品"的系统性风险,下一步是建立出门清单。
- **结论**: 提炼必须产生新认知(从具体事件推到可操作的改进),否则只是小学生缩句。
- **结果**: 演示了 So what 追问如何把总结升级为提炼。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 读完几十页研报/资料/书籍,需要提炼出可以交付的核心观点时。
2. 写报告/PPT/邮件,材料很多但不知道"重点是什么"时。
3. 想检验一个结论是"有深度"还是"只是缩句"时。
4. 面试/汇报前要把一堆信息压缩成 3 条核心判断时。

### 语言信号 (用户的话里出现这些就应激活)

- "帮我提炼一下核心观点" / "重点是什么?"
- "读完这些,得出什么结论?" / "帮我做个要点版"
- "这个结论是不是太浅了?" / "So what?" / "所以呢?"
- "synthesize the key points" / "what's the takeaway?" / "so what"

### 与相邻 skill 的区分

- 与 `hypothesis-driven-research` 的区别: 假设驱动是"怎么研究"(输入过程),金字塔是"怎么提炼"(处理输出)——研究完的结论交给金字塔加工。
- 与 `scqr-storyline` 的区别: 金字塔提炼出"结论是什么",SCQR 决定"怎么按受众讲出来"——金字塔在前(内容),SCQR 在后(表达)。
- 与 `research-source-filtering` 的区别: 来源筛选是输入端的质量把关,本 skill 是处理端的提炼。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **罗列资讯,写完整语句**
   - 把所有重要资讯整理成完整句子(能独立成立,不是关键词碎片)。
   - 判停条件: 若资讯量太少(≤3 条)或本身就是单一结论,先判断是否有提炼必要;资料不足先去研究(假设驱动)。
   - 完成标准: 资讯清单,每条一句完整陈述。

2. **分组 + 提炼要点(MECE)**
   - 找共性分组,确保组间不重叠、组内能穷尽。
   - 每组提炼一句话关键论述(用归纳/演绎补足推理)。
   - 完成标准: 分组表(组名 + 组内条目 + 提炼要点)。

3. **归纳核心 + So what 追问**
   - 反复问"这组要点对问题意味着什么",逐层上推直到得出可操作的顶层结论。
   - 检验:这个结论是否产生新认知?是否改变决策或下一步行动?若只是复述原文,继续问 So what 或标注"这是总结非提炼"。
   - 完成标准: 输出"顶层核心观点 + 支撑它的金字塔结构 + 一个 So what 结论"。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 内容改写成缩句/摘要——那是总结,不是提炼,别混淆。
- 纯信息查询(用户要的是事实列表)——不需要金字塔加工。
- 排版/格式整理——那是另一回事。

### 作者在书中警告的失败模式

- **把"总结"当"提炼"**(ce21):结论部分只是事实的复述,没有信息增量——缺 So what 追问是通病。
- **MECE 违反**(ce38 同源):分组重叠或遗漏,导致论证不完整。
- **停留在 Know-what**:只罗列"是什么",不推到"怎么办/为什么",观点没有深度。

### 作者的盲点 / 时代局限

- **深度差悖论**(ce46):金字塔能保证"不犯大错、快速建立认知基线",但要产生超越共识的洞察,还需框架之外的反共识——金字塔本身不产出超额认知。
- **AI 辅助局限**(ce29/ce32):让 AI 做金字塔四步时,其输出同样可能只是"看似有条理的总结",要自己追问 So what 并把关提炼质量。

### 容易混淆的邻近方法论

- 与"摘要/缩写"混淆:摘要忠于原文(总结),提炼超越原文(So what)。
- 与"SCQR 故事线"混淆:金字塔组织"内容结构",SCQR 组织"表达顺序"。
