# 商业模式可行性评估两步法

## R — 原文 (Reading)

> "商业模式的可行性评估可以分为两步:销售可行性评估和利润可行性评估。前者主要评估产品或服务能不能卖得出去，后者主要评估它们到底能不能赚到钱。"
>
> — 肖璟，《如何快速了解一个行业》第2章 第3节

## I — 方法论骨架 (Interpretation)

判断一个早期商业模式能不能成立,分成两个独立的关卡,两步都通过才算可行。

**第一步,销售可行性:需求到底真不真。** 用两个"对标"验证——时间对标(往前回溯,这个需求历史上是否以别的形式被满足过?如果从没存在过类似需求,大概率是伪需求)和空间对标(对标成熟市场,别处有没有已经成功的类似案例?底层假设是人类需求相通)。再配合一个排序工具:需求按**频次**(高/低)和**弹性**(小/大)排优先级,频次高或弹性小至少取其一,才可能有不差的收入。

**第二步,利润可行性:赚不赚得到钱。** 找到能体现收入和成本关系的"最小运作单位"(单店/单客/单车/单单/单品),搭它的经济模型(UE 模型)——最小单位赚不到钱,规模化大概率也难。关键要用**终局视角**动态看:当前亏损不代表永远亏损,要同时建"当前/盈亏平衡/终局"三个模型;只有当当前亏损且没有向盈亏平衡演进的路径时,才判定商业模式大概率不可行。

## A1 — 书中的应用 (Past Application)

### 案例 1:海底捞单店模型——UE 模型搭建与关键指标
- **问题**: 判断海底捞的开店扩张是否可持续,需要看清单店到底赚不赚钱、由什么决定。
- **方法论的使用**: 拆解 2019 年单店 UE:营收=客单价 105.20 元×日均 1260 人次(75 桌×3.5 人×4.8 翻台)×360 天≈4772 万元,再逐项拆成本(食材/员工/折旧/租金/水电),经营利润约 888 万元。关键指标是**翻台率**。
- **结论**: 翻台率 4.8 次/天是不错成绩;2021-2022 跌至 3,说明开店密度提高稀释客流。
- **结果**: 海底捞 2020 年启动"啄木鸟计划",把翻台率 4 次/天设为扩店前提——UE 模型直接驱动了经营决策。

### 案例 2:美团外卖——终局视角看早期亏损
- **问题**: 外卖早期每单严重亏损,按静态 UE 似乎商业模式不可行。
- **方法论的使用**: 用终局视角预测——随着渗透率提升、订单密度增加(一栋楼从一两人点到一两百人点),配送员单次跑腿订单数大增,每单配送成本下降。
- **结论**: 东吴证券测算 2021 年美团每单配送成本比 2020 年降 0.2 元,叠加佣金提高,每单毛利增 0.19 元。
- **结果**: 从单均亏损到单均毛利转正,验证"当前亏损≠不可行"。

### 案例 3:共享篮球——时间对标法识别伪需求
- **问题**: 共享经济风口下,共享篮球看起来"很有需求"。
- **方法论的使用**: 时间对标——过去从来没有篮球租赁服务。原因:篮球便宜不占地、爱好者家中常备;打篮球的前置成本(换装/约人/订场)远超租球的便利。App 只解决了本就不是痛点的环节。
- **结论**: 伪需求,不值得投资。
- **结果**: 共享篮球项目很快凉了。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 评估一个创业想法/BP,想判断"这个到底能不能成"时。
2. 拿到一个新项目(自己的或别人的),想快速验证需求真假、别被"看起来有需求"骗了时。
3. 投资一个导入期/早期行业或公司,需要判断商业模式是否跑得通时。
4. 想搞清一个陌生业务"靠什么赚钱、为什么赚钱"时。

### 语言信号 (用户的话里出现这些就应激活)

- "这个项目能成吗?" / "这是不是伪需求?" / "这么做能赚钱吗?"
- "帮我分析下这个商业模式" / "它靠什么赚钱"
- "单店模型 / 单位经济 / UE / 翻台率"
- "is this business model viable?" / "is this a fake demand?" / "unit economics"

### 与相邻 skill 的区分

- 与 `industry-lifecycle-staging` 的区别: 本 skill 是导入期阶段的研究重点;行业已进入成长/成熟期则转去市场规模/护城河,不应反复验可行性。
- 与 `market-sizing` 的区别: 可行性问"能不能成",市场规模问"能有多大"——先验可行性(尤其导入期),再算天花板。
- 与 `moat-analysis` 的区别: 可行性是"活不活得下去",护城河是"守不守得住"——护城河是成熟期分析,可行性是导入期分析。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **拆解商业模式要素,明确目标客户与价值主张**
   - 用商业模式画布(或生产力×生产关系排列组合)把业务拆开:谁、为什么、付什么钱、从哪收钱。
   - 判断这个业务在满足"新需求"还是"旧需求的新满足方式"——后者胜率高。
   - 完成标准: 一句话说清"为谁提供什么价值、如何收费"。

2. **验销售可行性:时间对标 + 空间对标 + 频次弹性排序**
   - 时间对标: 历史上是否有同类需求的先例?若无,标注"疑似伪需求"。
   - 空间对标: 成熟市场/发达地区是否有成功案例?注意对标对象本身若是新生事物,参考价值存疑。
   - 用频次×弹性矩阵给需求排优先级,频次和弹性都差则收入潜力堪忧。
   - 判停条件: 若销售可行性明显不成立(历史无需求 + 无成熟对标 + 频次弹性双低),直接判"不可行",无需进入第二步。
   - 完成标准: 对"需求真不真"给出明确判断 + 至少两个独立证据。

3. **验利润可行性:搭最小运作单位 UE 模型,并用终局视角看演进**
   - 找到最小运作单位,列出收入与成本结构,算出当前 UE。
   - 找到决定该 UE 的关键指标(如餐饮翻台率、外卖订单密度)。
   - 建立当前/盈亏平衡/终局三个情景,判断亏损能否随规模改善。
   - 判停条件: 若当前亏损且无向盈亏平衡演进的路径,判"大概率不可行"。
   - 完成标准: 输出"可行/不可行/需观察"+ 决定性理由 + 关键监测指标。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 分析已进入成长/成熟期的行业——那阶段的重点不再是验可行性,而是规模、护城河与竞争格局。
- 需要精确估值定价时——本 skill 判断"能不能成",不回答"值多少钱"。

### 作者在书中警告的失败模式

- **马斯洛金字塔的"似是而非"陷阱**(ce05):任何产品抽象后都能贴上"满足了某种需求"的标签,但这不等于需求真实存在——金字塔不能单独作为需求成立的证据,必须做时间/空间对标。
- **空间对标对象本身是新生事物**(ce06):Clubhouse 火三个月就凉了,国内跟风者全部沉没——用"那边火了"作证据时,先确认对标对象需求已稳态验证。
- **静态 UE 一票否决**(ce07):外卖/共享单车早期单均亏损,规模化后扭亏——只有三个 UE 模型都无法向盈利演进时才判不可行。
- **光砸钱没有 know-how**(ce38):恒大冰泉 20 天砸 13 亿广告、3 年巨亏 40 亿——资本买不到行业 know-how,后者才是护城河。

### 作者的盲点 / 时代局限

- **UE 线性假设**:UE 模型隐含"最小单位赚钱则规模化可行",但对平台/网络效应型业务(规模报酬递增),当前 UE 亏损不说明不可行——作者虽补了终局视角,框架本质仍是线性的(来自阶段 0 批判)。
- **SaaS 水土不服**(ce41):商业模式可行性随外部因素(付费习惯、采购流程)变化,海外跑通的模式复制到中国可能失效。

### 容易混淆的邻近方法论

- 与"财务估值"(industry-valuation)混淆:可行性是定性+UE 的判断,估值是对已可行业务的定价,不要混用。
- 与"市场规模测算"混淆:先可行性后规模,顺序不要颠倒。
