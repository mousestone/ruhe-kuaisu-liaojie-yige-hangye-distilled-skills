# SCQR 故事线输出(按受众调整)

## R — 原文 (Reading)

> "S、C、Q、R这4个字母分别代表:情景(Situation)、冲突(Complication)、问题(Question)、解答(Resolution)。"
>
> — 肖璟，《如何快速了解一个行业》第11章 第3节

## I — 方法论骨架 (Interpretation)

把研究结论讲给别人听,和做研究是两套相反的顺序——"解题归解题,沟通归沟通"。研究从假设推到验证再到结论;沟通要反过来,先让人明白"为什么该听这个",再给结论。

**SCQR 四要素**:
- S 情景(Situation):建立共识的背景。
- C 冲突(Complication):发生了什么变化、出现了什么问题。
- Q 问题(Question):由此带来了什么问题。
- R 解答(Resolution):核心观点/结论,要快、准、狠。

**按受众调整顺序是关键**:
- **路人**(陌生、没耐心):CQSR——把冲突和问题放最前,用冲突抓眼球(适合短视频/开场)。
- **观众**(中立、想听完整逻辑):SCQR——经典顺序(适合演讲/电影)。
- **大老板**(忙、要决策):RSCQ——把解决方案放最前,先给结论再给背景(适合管理层汇报)。
- **直属领导**(熟悉、紧密协作):只给 R——直接说结论,省去铺垫。

不能刻舟求剑,同一个内容对不同受众要用不同顺序。问题不明显时可以把 Q 省略成 SCR。

## A1 — 书中的应用 (Past Application)

### 案例 1:陈楸帆导师反馈——解题 vs 沟通顺序反转
- **问题**: 在谷歌做核心客户画像项目,PPT 演示从研究方式→中间工作→结论→方案,演示到一半听众已走神。
- **方法论的使用**: 导师陈楸帆(科幻作家)点评:"你讲故事就像厨师先洗菜切菜堆一边,上菜时顾客已经不耐烦了。"研究过程是"备菜"顺序,沟通要反过来"先上菜"。
- **结论**: 解题顺序(假设→验证→方案)与沟通顺序(方案→依据)相反。
- **结果**: 作者领悟后加入麦肯锡系统学习 SCQR 框架。

### 案例 2:林肯葛底斯堡演说——SCQR 经典引入
- **问题**: 如何在几分钟的演说里抓住听众并带出核心主张?
- **方法论的使用**: 开头即经典 SCQ——情景("八十七年前先辈建立孕育自由的国家")→冲突("现在正在从事伟大的内战")→问题("我们来到这里是为了奉献什么")。
- **结论**: 好的引入把听众带到同一个情景,水到渠成引出核心观点。
- **结果**: 葛底斯堡演说成为被反复背诵的经典。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 写汇报 PPT/邮件/发言稿,内容已定但不知道怎么组织顺序时。
2. 向不同对象(老板/客户/同事/陌生听众)讲同一个结论,不知道该侧重哪里时。
3. 开场没吸引力、中间跑题、结论没冲击力时。
4. 把一份研究/分析结果"讲出来"而非"写出来"时。

### 语言信号 (用户的话里出现这些就应激活)

- "帮我写个汇报 / 演讲稿 / 邮件" / "怎么向老板讲这个?"
- "帮我组织一下顺序" / "听众是谁?怎么开场?"
- "SCQR / 空雨湿伞" / "先讲结论还是先讲背景?"
- "how should I present this?" / "storyline" / "pitch this to the CEO"

### 与相邻 skill 的区分

- 与 `pyramid-insight-extraction` 的区别: 金字塔解决"结论是什么、内容怎么组织"(内容结构),SCQR 解决"怎么按受众讲出来"(表达顺序)——金字塔在前,SCQR 在后。
- 与 `hypothesis-driven-research` 的区别: 假设驱动是"解题"(研究过程),SCQR 是"沟通"(讲故事)——顺序相反,不要混用。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **明确受众与沟通目标**
   - 判断受众是谁:路人/观众/大老板/直属领导(或对应熟悉度与时间预算)。
   - 明确这次沟通要达成的结果(让对方做什么/信什么)。
   - 判停条件: 若内容本身还没提炼出核心结论,先移交 `pyramid-insight-extraction`。
   - 完成标准: 一句话"受众是谁 + 希望对方做什么"。

2. **搭 SCQR 四要素,按受众排序**
   - 写出 S/C/Q/R 四段内容(结论要快准狠)。
   - 按受众选顺序:路人 CQSR / 观众 SCQR / 大老板 RSCQ / 直属领导只给 R。
   - 问题不明显则省略 Q(SCR)。
   - 完成标准: 一个按受众排序的故事线大纲(S→C→Q→R 各段一句)。

3. **打磨引入与衔接,检查"上菜"逻辑**
   - 开场必须抓住注意力(冲突前置或用情景建立共鸣)。
   - 检查是否符合"沟通顺序=结论优先于铺垫"(对忙的受众)。
   - 通读一遍,确认结论在受众最容易接受的位置出现。
   - 完成标准: 输出可直接用的故事线 + 开场白 + 结论句。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 内容提炼/研究分析(那是金字塔/假设驱动的活)——SCQR 是"讲出来"这一步。
- 事实查询——不需要组织故事线。
- 纯文字材料(学术论文、报告正文)而非口头/演示沟通——不同载体逻辑不同。

### 作者在书中警告的失败模式

- **SCQR 生搬硬套**(ce22):不管受众都用同一顺序,对大老板绕弯子铺垫、对路人先讲方案,受众全得罪。
- **解题顺序当沟通顺序**(c58):把研究过程(先洗菜切菜)直接当汇报(先上菜),听众早就走神。
- **结论藏在最后**:对忙碌的受众(大老板)把结论放最后,等于让决策者听完全部铺垫才见核心——顺序选错,沟通失败。

### 作者的盲点 / 时代局限

- **书面沟通的边界**:SCQR 主要针对口头/演示/短视频场景,书面报告(尤其是需要严谨论证的文档)不一定适用。

### 容易混淆的邻近方法论

- 与"金字塔原理"混淆:金字塔是内容组织,SCQR 是叙事顺序——两者配合(金字塔提炼出结论,SCQR 包装着讲)。
- 与"即兴演讲技巧"混淆:SCQR 是结构框架,不是口才技巧。
