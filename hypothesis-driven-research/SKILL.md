# 假设驱动研究法(研究资讯处理的底层方法论)

## R — 原文 (Reading)

> "与其耗费大量的时间和精力去搜集资讯、筛选资讯，我们不如采用更加高效的方法--假设驱动，这也是做研究的底层方法论。它可以分成以下3个步骤:做出假设、拆解假设、验证子假设。"
>
> — 肖璟，《如何快速了解一个行业》第11章 第1节

## I — 方法论骨架 (Interpretation)

研究复杂问题的第一原则:**不要大海捞针**。别一上来就漫无目的地搜资料,而是带着假设去验证。

**三步法**:
1. **做出假设**——基于逻辑与常识,对问题原因做合理推断(可证实伪)。
2. **拆解假设**——按 MECE(不重不漏)原则,把总假设拆成所有可能情形的子假设。同一层分项不重叠、加总为全集。
3. **验证子假设**——为每个子假设找到可论证的指标/数据,从统计局、央行、数据终端获取。子假设全验证则总假设成立。

**为什么研究**:研究创造三种信息差——时间差(比人快,可遇不可求)、广度差(覆盖广,易致 FOMO)、深度差(对供给侧或需求侧认知更深)。**深度差是持续创造财富的唯一可靠前提**,应先在一个领域深耕具备深度差,再追求广度。

**处理资讯时的两个底层区分**:
- 事实判断(回答"是什么",有精确值)vs 价值判断(回答"应该怎样",无上下之分只有左右之别)——客观评价和预测应基于事实判断,参考他人价值判断前先确认其有事实与逻辑支撑。
- 避开观点极化三招:关闭算法推荐跳出信息茧房、主动关注异见并尝试证伪、用系统2理性赋权(数据驱动)而非系统1直觉。

**工具纪律**:生成式 AI 可贯穿全流程(转写/总结/假设拆解/写代码分析/生成文稿),但 AI 有三局限(回答不稳定、无深度推理、训练数据时效滞后),输出必须查证——尤其投资研究涉及真金白银。

## A1 — 书中的应用 (Past Application)

### 案例 1:"消费降级"研究——MECE 拆解子假设
- **问题**: 网上"消费降级"众说纷纭,5500 万条搜索结果无从下手。
- **方法论的使用**: 步骤 1 假设:消费降级是因为钱不够花了;步骤 2 MECE 拆解:"钱不够花"=收入变少(主动收入+被动收入)或支出变多(应付本金利息+投资),得 4 个子假设;步骤 3 验证:到统计局/央行找指标逐项验证。
- **结论**: 把"5500 万搜索结果"的问题变成 4 个可验证的指标。
- **结果**: 高效收敛,避免大海捞针。

### 案例 2:作者 2017 投资腾讯——需求侧深度差
- **问题**: 凭什么在 270-300 港元买入腾讯?
- **方法论的使用**: 建立需求侧深度差——两个观察:平时不玩游戏的好友玩起了《王者荣耀》;环游中国时发现街头/餐馆等位的人都在玩。
- **结论**: "春江水暖鸭先知",对市场需求的细致观察是深度差的来源。
- **结果**: 270-300 港元买入,500-600 港元卖出,获利离场。

### 案例 3:胡博予试驾特斯拉——深度差来自亲自验证
- **问题**: 2013 年如何判断特斯拉值不值得买?
- **方法论的使用**: 看完 Consumer Reports 的"完美车评"后,跑去门店试驾 Model S,再刷遍海外车评和提车报告——从需求侧建立深度差。
- **结论**: 没有调查就没有发言权。
- **结果**: 买入后不到一年股价"起飞",赚近 3 倍离场。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 接到开放式研究任务("研究一下为什么 X""搞清 Y 的影响")时。
2. 面对一个信息过载、众说纷纭的问题(网络争论/社会现象/行业变化)时。
3. 需要为一个判断建立可验证的依据,而不是听风就是雨时。
4. 想系统学习一个新领域,但不知从何入手时(假设+拆解+验证可拆成子问题)。

### 语言信号 (用户的话里出现这些就应激活)

- "帮我研究一下 XX" / "为什么 XX 会这样?" / "XX 的原因是什么?"
- "该怎么入手研究?" / "信息太多了从哪开始?"
- "假设驱动 / MECE / 拆解" / "深度差 / 信息差"
- "research why X" / "root cause" / "hypothesis-driven" / "how to approach this problem"

### 与相邻 skill 的区分

- 与 `pyramid-insight-extraction` 的区别: 假设驱动解决"怎么高效找到答案"(研究过程),金字塔解决"怎么把结论提炼表达"(处理输出)——研究在前,提炼在后。
- 与 `scqr-storyline` 的区别: 本 skill 是"解题"(研究),SCQR 是"沟通"(讲故事)——解题归解题,沟通归沟通,两者顺序相反。
- 与 `research-source-filtering` 的区别: 前者是"怎么研究的方法",后者是"怎么挑数据源/研报"——来源筛选是研究执行中的一环。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **做出假设,并明确研究目标**
   - 用一句话定义要回答的问题(不要泛化成"了解 XX 行业")。
   - 基于常识对最可能的原因做 1-3 个可证伪的假设。
   - 判停条件: 若问题已有明确的单一答案(查资料即可),不进入本 skill,直接查证。
   - 完成标准: 研究问题一句话 + 假设列表 + 每个假设的可证伪性说明。

2. **MECE 拆解子假设,为每个子假设找验证指标**
   - 把每个假设拆成互不重叠、合起来穷尽的子假设。
   - 为每个子假设指定可获取的指标/数据源(统计局/央行/数据终端/调研)。
   - 判停条件: 若某个子假设找不到任何可验证指标,拆到可验证为止或明确标注"不可验证,降级为推测"。
   - 完成标准: 假设树(MECE 无重叠无遗漏) + 指标-数据源映射表。

3. **验证子假设,汇总结论,查证 AI 输出**
   - 逐项获取数据验证,标注验证结果(支持/反对/中性)。
   - 若用了生成式 AI 辅助,对每个关键数字/事实回溯原始信源。
   - 汇总:子假设验证 → 总假设成立与否 → 给出有 So what 的结论(移交金字塔提炼)。
   - 完成标准: 结论 + 证据链(哪些子假设被验证、证据是什么) + 仍不确定的部分。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 已有明确答案的简单查证(直接检索,不要为了用框架而用框架)。
- 纯表达/写作任务——那是金字塔/SCQR 的活。
- 一次性的"告诉我事实"式问答——假设驱动针对需要推理的开放问题。

### 作者在书中警告的失败模式

- **确认偏误与观点极化**(ce18):算法茧房只推同立场内容,持有观点后只看利好——必须主动拓宽输入、尝试证伪。
- **时间差陷阱**(ce19):微信群/小作文是第 N 手信息且混假消息——研究要基于可验证数据,不是消息。
- **广度差/FOMO**(ce20):追求覆盖面广而浅尝辄止,无法形成深度差——先深耕一个领域。
- **专家预测失准**(ce24):2015 年新能源专家悲观,结果行业成为"明星"——专家只提供微观事实,宏观趋势要用数据判断,且要评估其认知边界(ce25)。
- **AI 幻觉/不稳定/变笨**(ce29/ce30/ce31):AI 一本正经胡说八道、答案每次不同、知识停在训练时点——输出必须查证(ce32)。

### 作者的盲点 / 时代局限

- **深度差悖论**(ce46):当大家都用同一套框架时,深度差被共识抹平——框架保证"不犯大错",超额收益需框架之外的反共识。
- **强投资视角**(ce48):"研究"在本书记载为投资服务,其他用途(求职/学术/媒体)的深度差定义不同。

### 容易混淆的邻近方法论

- 与"系统性文献综述/资料汇编"混淆:那是全面覆盖(大海捞针的升级版),假设驱动是有目标的验证——两者目标不同。
- 与"金字塔原理"混淆:金字塔是输出组织,本 skill 是输入与研究组织。
